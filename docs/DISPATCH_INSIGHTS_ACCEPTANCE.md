# Dispatch custody, calendar, performance and duration acceptance

## Audit and scope
Extended the existing dispatch board, job controls, replacement history, protected RPCs and bulk review. Existing delivery lifecycle, customer-approved schedule changes, ledger and role gates were preserved. Delivery start/end windows and handover acknowledgement already existed; named custody summaries, daily driver calendar, authoritative performance aggregates and sourced durations were missing.

## Results
- **Custody — PASS:** admin-only parcel list derives in-transit/current custodian from recorded pickup and current responsibility. Pending handovers retain the old custodian until both acknowledgements. Cancelled/failed collected parcels remain custody-review items, not silently removed. Job workspace retains existing acknowledgement history. Disposable in-transit record read back with the correct driver.
- **Calendar — PASS:** seven-day Harare calendar, driver rows, daily commitments, clickable job workspace and warning highlights for actual overlap or incomplete competing windows. Separate week/driver controls; bounded 501 commitments with truncation warning. Desktop populated screenshot and mobile overflow check passed. Unscheduled commitments appear as conflict reasons, not fabricated calendar times. Live manual offers remain reserved by assignment validation but are not calendar event rows.
- **Performance — PARTIALLY COMPLETE:** database aggregates delivered, timed/on-time, late, timing-unknown and cancelled jobs with separate active workload; selected cohort uses delivery creation date. Cancellation is not labelled driver fault. Bulk review includes last-30-day comparison. Explicit disposable results of one on-time, one late, two timed and one cancellation passed. Payout request history reads existing recorded withdrawal statuses without claiming transfers; populated payout history was not tested because no genuine payout was manufactured. Empty-state browser passed.
- **Durations and alternatives — PASS for tested planning workflow:** explicit job duration, source, admin/time and audited reason; persisted 45 minutes with derived 08:45 end for an 08:00 start. Browser record/save/refresh passed. Existing reserved/assigned jobs cannot have duration silently changed; participant-approved schedules remain separate. Driver conflict checks suggest up to three 30-minute-grid alternatives in the next seven days only with recorded duration and declared same-day working hours. Suggested first slot after a conflicting 08:00–09:00 job passed. No travel-time inference or automatic scheduling. Source is administrator-supplied evidence, not externally certified.

## Changes
Additive migration 0026 adds four delivery duration/source/recorder fields, protected duration guard, audited `admin_record_delivery_duration`, `admin_dispatch_insights`, `admin_delivery_alternatives`. New server wrappers use existing authenticated middleware; RPCs validate stored admin role. No new table or public read policy. New views are presentation modes within the existing dispatch route, retaining its unique metadata; index metadata remains intact.

## Verification
- 24 unit tests passed: duration schemas, dispatch schemas, assignment schemas and payment policy.
- Repeatable `tests/dispatch-insights-workflows.py` passed: source/duration/end/identity readback, conflict-aware alternatives, actual custodian/calendar records, non-admin denial, concrete performance counts, browser duration persistence, populated desktop views, mobile no page overflow and no runtime page errors.
- Existing `tests/dispatch-v31-workflows.py` passed: replacement acceptance, two-custodian handover, rejection, three offers/capacity, replay, overlap/non-overlap, bulk browser confirmation, same-job race, partial outcomes, provider interval checks, missing end-times, simultaneous overlapping offers, offline denial and non-admin denial.
- Latest preview compilation: build OK. Temporary deliveries and accounts removed; database count confirmed zero disposable deliveries. No real jobs, provider approvals, wallets or payments altered.

## Limitations
Payout history with populated financial records remains unverified; no real payout was fabricated. The calendar has its own week/driver controls rather than applying every board search filter. At most 200 drivers, 100 custody entries and 100 payout records are returned; larger fleets require additional pagination. Alternative suggestions rely on truthful sourced durations and declared working hours, reserve no slot and must be rechecked through existing approved scheduling/assignment operations. Overnight hours, route/travel feasibility, business-parent scheduling and automatic prediction are not implemented.
